# NEXUS AI: решения и проверенные уроки

## Контекст перед реализацией — 13.11.2026

- Фактический стек: Next.js 16.3.5, React 19.3, Supabase Auth/Postgres/RLS, Vercel. Упоминания Firebase в задании не соответствуют репозиторию; перенос авторизации и данных не нужен.
- Существующий AI использует OpenRouter, бесплатную маршрутизацию и серверные квоты. История хранится в памяти вкладки; streaming и инструменты отсутствуют.
- Сохранять бесплатный режим по умолчанию. Каждая попытка обращения к модели, включая fallback и шаги агента, должна учитываться; платный провайдер требует явной конфигурации бюджета.
- У пользователя пока нет ключа Search API. Отсутствие поиска необходимо показывать честно; готовый адаптер и тесты с подменой API не доказывают работающий интернет-поиск.
- Чужие сообщения, закрытые данные и service-role клиент не должны попадать во внутренние инструменты. Использовать клиента текущей сессии и явную проекцию полей.
- Ветка `codex/nexus-ai-agent` создана от актуальной `origin/main` (8eafdb4) в отдельной копии. Независимая работа над повтором отправки сообщений в неё не включается.
- Локальные тесты, браузер с подменёнными сервисами, реальный AI, настоящий Search API и production — отдельные уровни проверки.

## План интеграции

1. Добавить серверную конфигурацию, versioned prompt и ограниченный agent loop с потоковой передачей и типизированными инструментами.
2. Добавить новую миграцию для истории, запусков и добровольной памяти; сохранить RLS, идемпотентность, ограниченные квоты и защиту конкурентных запросов.
3. Подключить безопасный калькулятор, Brave Search, чтение публичных страниц с фиксацией DNS-адреса и разрешённые инструменты NEXUS.
4. Обновить существующий интерфейс: история, режимы, источники, действия, остановка, повтор, формулы, согласие и настройки памяти.
5. Проверить права, сбои/лимиты, SSRF, поток, типы, линтер, сборку и браузер; документировать условия настоящего запуска и выпуска.

## Границы этапа

- Длительные фоновые задания и исполнение кода требуют отдельной инфраструктуры; не имитировать восстановление вычисления после остановки процесса.
- Черновик публикации — редактируемый текст без автоматической публикации. Мутации социальных данных не предоставляются модели.
- Новые миграции подготовить и проверить отдельно от production. Выпуск производить только после проверки конкретного результата.

## Проверка 16.11.2026

- Next.js 16.4.6 в dev формирует `request.url` с `localhost`, даже если запрос пришёл через `127.0.0.1`. Браузерный тест выявил 403. Разрешено только точное совпадение локального `Origin` с `Host`, портом и протоколом при `Sec-Fetch-Site: same-origin`. Межсайтовый POST по-прежнему отклоняется.
- Перед поиском ограничивай объём доказательств в байтах. В историю сохраняй только данные о ссылках. В браузере проверяй форму результата из БД и разрешай клики только для безопасных адресов. При сохранении с ошибкой оставляй полученный поток для копирования.
- Сохраняй последний доступный запрос к модели для ответа. Если резюме истории не удалось, сохраняй предыдущую сводку и продолжай с ограниченным контекстом. Учитывай общий лимит, индивидуальный лимит и оставшиеся обращения в скользящей минуте.
- DNS-запрос Node.js может запросить все адреса даже при фиксации на одном IP. Для `options.all` верни массив с единственным ранее проверенным адресом. Живое чтение IANA и публичного `robots.txt` прошло.
- Бесплатный OpenRouter успешно выполнил калькулятор, чтение ссылки и разбор Python. Иногда ограничивает быструю модель. Brave проверен только на подменённых ответах из-за отсутствия ключа.

## Наблюдения после первого прохода

- Вызов `openrouter/free` 13.11.2026 подтвердил связку AI SDK → модель → калькулятор → финальный ответ. Синтетический вопрос стоил $0 по бесплатному маршруту. Для подтверждения входа, квот, истории и поведения интерфейса нужен отдельный тест через `/ai` с тестовой базой.
- Локальный ключ модели и серверный ключ проекта Vercel имеют разное назначение. Рабочий ключ хранится в закрытом `.env.local` или в серверных переменных целевого окружения. В отчёты и тестовые журналы записываются только результаты и коды ошибок.
- Тесты политики RLS исполняют PostgreSQL в PGlite. Они помогают проверить владельца и переходы состояния, а проверка нескольких одновременных сессий Supabase нужна для подтверждения интеграции.
- При воспроизведении сетевого чтения с Node 24 закреплённый DNS lookup должен поддерживать форму ответа для `options.all`. Иначе системный сетевой код получает некорректный адрес даже при успешной проверке DNS. Менять URL при проверке следует только между заново проверенными переходами.
- При обновлении зависимостей проверяйте фактические транзитивные версии рендерера формул и сетевых пакетов в lock-файле. Перед выпуском гоняйте production build с тем же Node, что в CI.

## Условие выпуска — 17.11.2026

- Пользователь подтвердил замену текущего AI после всех проверок и уточнил, что рабочий веб-поиск обязателен. Один лишь адаптер, подмена API и чтение URL не закрывают этот сценарий. Остальные проверки продолжать в изолированной среде.
- Для бесплатной проверки добавлен Firecrawl API наряду с Brave. Провайдер в согласии пользователя соответствует конфигурации. Ключи модели и поисковика передаются только на согласованные серверные адреса. Адаптер ограничивает выдачу и не использует платное чтение страницы.
- Проверяй облачную схему GET с проекцией и нулевым размером выборки. Запрос HEAD к отсутствующей таблице вернул 204 без счётчика, а GET подтвердил отсутствие таблиц AI (`PGRST205`). Таблица квот в тестовом проекте существует.
- CI на npm 11.19.1 отклонил lock-файл, сформированный npm 11.6.1 на macOS: недоставало записей `@emnapi/core` и `@emnapi/runtime` для Linux. Пересобирай lock-файл версией CI и проверяй `npm ci` для Linux при изменениях кроссплатформенных зависимостей.
- Тестовый пароль из двух UUID с префиксом превысил ограничение Supabase Auth. Один UUID с префиксом прошёл. Проверка облачной БД с тестовым потоком модели успешно отделила результат Auth/RLS от временного ограничения реального OpenRouter.
- Действующий ключ Firecrawl подтвердили отдельно вызовом API и в режиме исследования NEXUS с изолированным Supabase. Тестовый поток выбирал `researchTopic`, а ссылки пришли из настоящих запросов Firecrawl. Этот прогон проверяет интеграцию поиска, вывод реальной модели остаётся отдельной проверкой. При сбое очистки проверяй и удаляй конкретный временный аккаунт по ID и признакам фикстуры.

## Проверка реальной модели и квот — 17.11.2026

- В изолированном Supabase два авторизованных аккаунта одновременно завершили «Быстрый ответ» и «Решение задачи» через настоящий OpenRouter. Быстрый режим сделал один модельный вызов, агент в режиме решения вызвал калькулятор и получил 400. Прошли поток NDJSON, учёт квоты, повтор запроса, изоляция и удаление истории, согласие на память и очистка памяти.
- Сквозной сценарий «Исследование» с реальной моделью остановился на `provider_capacity`. OpenRouter вернул 429 с `limit_source: upstream_provider_shared_pool`, что означает нехватку мощности у поставщика модели. Сквозной прогон остался красным. Прогон с тестовой моделью и настоящим Firecrawl подтверждает ссылки и вызов поиска отдельно. Полное исследование требует живого финального ответа по найденным источникам.
- `provider_capacity` допускает резервный бесплатный маршрут при оставшейся квоте. При других 429, денежных ограничениях или исчерпании квоты регистрируется соответствующая ошибка. Для диагностики сохраняй только безопасный код. При необходимости сверяй `free_model_daily_requests` через `GET /api/v1/key` с того же серверного ключа и не записывай ключ или полное тело ответа в журнал. [Документация OpenRouter по лимитам](https://openrouter.ai/docs/api-reference/limits).
- OpenRouter считает дневную квоту бесплатных вариантов по сумме когда-либо приобретённых кредитов. Базовый лимит — 50 обращений в сутки, после покупки $10 кредитов — до 1 000, с допуском от $9 по руководству провайдера. Потолок 20 обращений в минуту сохраняется. Стоимость бесплатных моделей остаётся $0. Дневная квота аккаунта и наличие свободной мощности у поставщика — разные ограничения. [Бесплатные модели OpenRouter](https://openrouter.ai/collections/free-models/).
- Ветка допускает дневную настройку до 1 000 обращений в конфигурации и миграции [202611170001_ai_quota_ceiling.sql](../../supabase/migrations/202611170001_ai_quota_ceiling.sql). Миграция расширяет диапазон ограничений без изменения строк квот и счётчиков. Значения приложения по умолчанию — 5 на пользователя и 40 на проект. Действующий лимит задаётся меньшим из настроек БД и приложения, отдельно действует глобальный предел 20 обращений за скользящую минуту. Расширение диапазона в коде не подтверждает повышение лимита аккаунта OpenRouter. Все 170 локальных тестов прошли.

## Groq Free и экономия исследования — 18.11.2026

- Пользователь требует денежный расход $0 и разрешил вход в Groq Free, принятие условий и отдельный серверный ключ. В нативном Chrome подтверждён Billing Current Plan за $0. Создан отдельный ключ и сохранён в исключённом `.env.groq.local` с правами `0600`. Флаг `AI_GROQ_FREE_CONFIRMED=true` допустим после этой проверки фактической организации.
- Адаптер Groq ограничен точным `https://api.groq.com/openai/v1`, ключом `AI_API_KEY`, бесплатной конфигурацией и подтверждением плана. Основная модель по умолчанию — `openai/gpt-oss-20b`, резерв отсутствует. Каталог проверяет активность. Для инструментов код допускает GPT OSS 20B и 120B с подтверждённой поддержкой локальных инструментов по документации. [Инструменты Groq](https://console.groq.com/docs/tool-use/overview).
- Исследование ограничено тремя шагами модели и тремя инструментами. Первый инструмент делает 2–3 независимых запроса параллельно и сохраняет успешную выдачу при частичном отказе. Второй шаг может прочитать ключевые страницы, третий завершает сравнение. Время и бюджет модели по-прежнему ограничивают исполнение.
- По документации Groq GPT OSS Free имеет 200 000 токенов в сутки наряду с ограничением количества вызовов. Firecrawl Free даёт 500 поисков в месяц. Число готовых ответов рассчитывай из реального расхода токенов и поисков по всем шагам. При трёх поисках один запуск исследования занимает три из месячных 500. [Лимиты Groq](https://console.groq.com/docs/rate-limits) · [Тариф Firecrawl](https://www.firecrawl.dev/pricing).


## Подтверждённый Groq Free — 18.11.2026

- Для Groq используй нативный `@ai-sdk/groq` 4.0.85. Совместимый адаптер терял `x_groq.usage` и нужный формат сообщений с инструментами. Нативный адаптер позволил проверить учёт токенов и завершить многошаговое исследование. GPT OSS получает `include_reasoning=false` и по умолчанию `reasoning_effort=low`.
- Сквозной тест локального NEXUS с изолированным Supabase, Groq и Firecrawl прошёл. Быстрый ответ занял 1 вызов и 823 токена. Решение заняло 2 вызова и 2 737 токенов, калькулятор вернул 400. Исследование завершилось за 3 модельных вызова с 2 инструментами, 2 запросами поиска, 6 источниками и 6 583 токенами. Указан общий расход токенов по журналу, разбиение на вход и выход в этом результате не фиксировалось.
- В том же прогоне подтверждены одновременные ответы двух аккаунтов, поток NDJSON, квоты, повтор, изоляция и удаление истории, согласие на память и очистка памяти. Все три одноразовых аккаунта удалены. После прогона добавлен строгий отказ при незавершённом потоке модели, отдельная регрессия прошла.
- На этом этапе прошли 177 локальных тестов, типы, ESLint, production-сборка Webpack и Linux dry-run `npm ci` на npm 11.19.1. Для оценки доступного объёма ответов проверяй фактические квоты организации.

## Финальный ответ исследования Groq — 24.11.2026

- В защищённом Preview `d2c8353` Firecrawl вернул источники и страница прочиталась, затем финальный поток Groq вернул `invalid_request_error` (400) до первого фрагмента ответа. Сверяй этап по безопасной категории ошибки и счётчикам модели, инструментов и поиска. Не журналируй вопросы, аргументы инструментов и необработанные ответы провайдера.
- На финальном шаге исследования Groq передавай исходные сообщения и уже собранные ограниченные по размеру материалы как явно недоверенные данные. Убери из этого шага протокольные сообщения вызовов инструментов и укажи модели завершить ответ по имеющимся материалам. Проверь, что промежуточные шаги по-прежнему получают штатные результаты функций.
- В Preview `fb24e1a` этот сценарий завершился за 7,6 с. Три вызова Groq, два запроса Firecrawl, шесть ссылок, одна прочитанная страница, 5 509 входных и 1 370 выходных токенов, $0 по Free. История сохранена, временный аккаунт удалён. Ссылки доступны в карточках источников. URL внутри текста ответа в этом прогоне не было.
